## 22.1. Процедурный материал: что это

Процедурный материал — это **граф нод**, а не картинка:

```
Координаты → Mapping (растяжение) → Текстура (шум/воронои/волна)
           → Color Ramp (два цвета) → Principled Base Color
                              ↘ Map Range → Roughness
                              ↘ Bump → Normal
```

Такой материал **не нужно запекать**, пока он живёт в Blender, и **нельзя
экспортировать** в игру без запекания. Но он даёт то, чего не даёт текстура:
бесконечное разрешение, отсутствие повторов и лёгкую настройку.

### Проблема, которую решает генератор

Каждый художник собирает такой граф **руками**, и каждый собирает его
по-своему. Два «деревянных» материала никогда не совпадают, и пересобрать
чужой невозможно.

Генератор решает это: **граф собирает код**, а не человек.

```
описание  →  модель выбирает рецепт и числа  →  код собирает граф
```

Модель хороша в том, чтобы понять «тёмное дерево с лаком» и плоха в том,
чтобы написать сто строк нод без опечатки. Здесь модель даёт только **числа**,
а код делает остальное — без ошибок API, с одинаковым результатом каждый раз.

## 22.2. Рецепты

Готовые заготовки — 16 штук:

| Рецепт | Паттерн | Что это | Ключевые слова |
|---|---|---|---|
| `wood` | noise + stretch | вытянутая текстура волокон, сильный бамп | дерево, доска, дуб |
| `marble` | noise + distortion | мягкие прожилки, полированная поверхность | мрамор, камень |
| `stone` | voronoi | крупная крошка камня | камень, гранит, бетон |
| `concrete` | noise | ровная шершавая поверхность | бетон, штукатурка |
| `rust` | voronoi | коррозия металла | ржавчина, оксид |
| `metal_brushed` | noise + stretch | штрихованный металл | металл, сталь, алюминий |
| `fabric` | wave | мягкая ткань | ткань, холст |
| `leather` | voronoi | кожа с порой | кожа |
| `paper` | noise | тонкий волокнистый лист | бумага, картон |
| `snow` | noise | мягкие белые надувы | снег, лёд |
| `lava` | voronoi | светящиеся трещины | лава, магма |
| `plastic` | noise | гладкий цветной пластик | пластик |
| `checker` | checker | шахматная доска | клетчатый |
| `brick` | brick | кирпичная стена со швами | кирпич, кладка, стена, wall |
| `tile` | brick (квадрат) | плитка с тонкими швами | плитка, кафель |
| `cobble` | brick | округлые камни с глубокими швами | булыжник, мостовая |

### Почему кирпич — отдельный паттерн

`pattern=brick` — это нода `ShaderNodeTexBrick`: ряды кирпичей, каждый второй
со сдвигом на половину, между ними — раствор. Нода сама знает и кирпичи, и
раствор, и разброс тона по кирпичам, поэтому цветовая рампа не нужна.

Цвета здесь значат **не то же, что в остальных паттернах**:

| Параметр | Смысл для кирпича |
|---|---|
| `color_a` | кирпич |
| `color_mid` | второй тон кирпича — разброс по кладке |
| `color_b` | раствор |
| `mortar_size` | ширина шва (0.02 — узкий, 0.06 — широкий) |
| `brick_width` / `row_height` | размер кирпича и ряда |
| `brick_bias` | сдвиг узора — кладка получается неровнее |

Фактор ноды (1 в растворе, 0 в кирпиче) делает две вещи: раствор **шероховее**
кирпича и, в инвертированном виде, **утоплен** в бамп — швы ниже, кирпичи
выше.

### Правило: шум — это туман

Самая частая ошибка процедурных материалов — **шум с цветовой рампой**. Это
облака, дым, пыль и прожилки мрамора — но никогда не кирпичная стена, не
плитка и не доска. Поверхности нужна **структура**: кирпичи, ячейки, волны,
волокно.

| Просят | Паттерн | Почему |
|---|---|---|
| кирпич, кладка, стена | `brick` | ряды кирпичей со швами |
| плитка, пол, кафель | `brick` (квадрат) | сетка плиток со швами |
| дерево, доска | `noise` + `stretch` (1, 12) | вытянутый шум читается как волокно |
| мрамор | `noise` + большой `distortion` | искажённый шум читается как прожилка |
| гранит, камень | `voronoi` | ячейки читаются как крошка камня |
| ржавчина | `voronoi` + `metallic` | пятна окисла |
| кожа | `voronoi`, мелкий масштаб | пористая поверхность |
| ткань | `wave` | нити |
| снег, дым, туман | `noise` | вот тут шум и нужен |

## 22.3. Как пользоваться

### Кнопка

**AI → Процедурные материалы → Процедурный**

Откроется поле для описания. Напиши, например:

```
тёмное дерево
```

или по-английски `dark wood`. Нажми Enter — материал соберётся.

⚠️ Кнопка **понимает только материал по ключевым словам**: «дерево» → wood,
«ржавчина» → rust. Для описания посложнее — спрашивай ассистента (ниже).

### Через ассистента

```
Сделай процедурный деревянный материал
```

```
Сделай ржавый металл: тёмно-оранжевый, очень шершавый, с сильным бампом
```

```
Покажи, какие есть процедурные рецепты
```

Ассистент видит каталог рецептов, выбирает нужный и подставляет числа.

### Что можно менять

| Параметр | Что делает |
|---|---|
| `pattern` | noise / voronoi / wave / checker / gradient / **brick** |
| `scale` | размер узора (больше — мельче) |
| `detail` | детализация шума |
| `distortion` | «размытие» узора — как у мрамора |
| `stretch` | растяжение по двум осям — из этого получаются волокна дерева |
| `color_a` / `color_b` | два цвета градиента (для кирпича: кирпич и раствор) |
| `color_mid` | третий цвет посередине (для кирпича: второй тон кладки) |
| `metallic` | металличность |
| `roughness` | шероховатость |
| `roughness_variation` | насколько шероховатость «плавает» по текстуре |
| `bump_strength` | сила рельефа |
| `specular` | блеск |
| `emission` / `emission_strength` | собственное свечение |
| `transmission` / `ior` | прозрачность и преломление |
| `mortar_size` / `brick_width` / `row_height` / `brick_bias` | раскладка кладки |

### Инструмент не угадывает: три правила

Знание о материалах лежит **в коде**, а не только в промпте, — иначе модель
забывает его на длинном контексте. Поэтому:

1. **`procedural.find`** — найти рецепт по словам пользователя. Слова
   сопоставляются с ключевыми словами рецептов *в коде*, а не моделью глазами
   по таблице в промпте.
2. **Рецепт можно назвать своим словом.** `procedural.build {"recipe":
   "кирпич"}` найдёт `brick` по ключевым словам — модель не обязана помнить
   имя рецепта.
3. **Без паттерна инструмент не строит ничего.** Раньше вызов без рецепта
   собирал материал по умолчанию: серый шум. Теперь инструмент отвечает
   «нужен паттерн» и перечисляет варианты. Молчаливый туман — худший
   исход, потому что пользователь получает не то, что просил, и не знает
   об этом.
4. **Материал сразу вешается на объект.** `procedural.build` назначает его
   активному объекту и пишет в отчёте, на что: «assigned it to 'Cube'».
   Иначе модель говорит «материал готов», а на объекте остаётся старый —
   пользователь видит ошибку, которой нет.

Отчёт инструмента тоже показывает, что именно построено
(`pattern=..., scale=..., roughness=..., bump=...`) — по нему модель видит,
дошли ли её параметры. Если имя материала похоже на рецепт с другим
паттерном (например, `BrickWall` собран из шума), в отчёт добавляется
напоминание.

## 22.4. Два технических решения

### Производная берётся на единицу UV

Это тот же приём, что и в карте нормалей из высоты: разница считается **на
единицу UV**, а не на пиксель. Иначе результат зависел бы от разрешения.

### Не у всех текстур есть выход «Fac»

У шума и волны есть `Fac`, у **Voronoi** — `Distance`, а у шахматной
текстуры и градиента скалярного выхода нет вовсе. Поэтому генератор берёт
подходящий выход автоматически:

```python
def _fac_output(node):
    for name in ("Fac", "Distance"):
        socket = node.outputs.get(name)
        if socket is not None:
            return socket
    return node.outputs[0]
```

⚠️ Наивная реализация (`texture.outputs["Fac"]`) падает на Voronoi — это
поймал тест.

## 22.5. Контекстное меню в шейдерном редакторе

**Правая кнопка мыши по узлу Image Texture** в Shader Editor:

```
┌──────────────────────────────────────┐
│ Asset Assistant                      │
│   Починить цветовое пространство     │
│   Упаковать в .blend                 │
│   Сделать путь относительным         │
│   ──────────────────────────────      │
│   Подключить в Base Color            │
│   Подключить в Roughness             │
│   Подключить в Normal                │
└──────────────────────────────────────┘
```

⚠️ Меню **расширяет** штатное меню Blender, а не заменяет его: стандартные
пункты (Copy, Paste, Delete) остаются на месте.

⚠️ Пункты появляются **только** для узла Image Texture: для остальных узлов
чинить нечего.

### Что делает каждый пункт

| Пункт | Что делает |
|---|---|
| **Починить цветовое пространство** | ставит `Non-Color` карте данных или `sRGB` цветовой. Понимает, куда картинка подключена |
| **Упаковать в .blend** | текстура едет вместе с файлом |
| **Сделать путь относительным** | путь `//textures/wood.png` вместо `D:/...` |
| **Подключить в Base Color / Roughness** | переподключает картинку в нужный сокет |
| **Подключить в Normal** | через узел **Normal Map** — карта нормалей, подключённая прямо в сокет, ломает рельеф |

## 22.6. Типичные проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| «Не понял, какой материал нужен» | в описании нет слова-ключа | назови материал прямо: «дерево», «ржавый металл» |
| Материал получился не тем цветом | цвета задаются двумя точками градиента | попроси: «сделай темнее» / «светлее» |
| Волокна не в ту сторону | растяжение по осям | попроси: «растяни по Y сильнее» |
| Рельеф слабый | `bump_strength` мал | попроси: «сделай рельеф сильнее» |
| Материал слишком пёстрый | шум с большой детализацией | уменьши `detail` |
| Градиент выглядит как каша | слишком узкий диапазон цвета | разведи `color_a` и `color_b` |

## 22.8. Скилл `material-procedural`

Ассистент знает о процедурных материалах из **скилла**
(`skills/material-procedural.md`), а не из памяти. Скилл — это проверяемый
файл с инструкцией и примерами кода; его примеры **исполняются на живом
Blender** в тестах, поэтому инструкция не может разойтись с API.

Что в скилле:

- как устроен процедурный материал (граф нод) и почему его лучше собирать
  кодом;
- таблица всех 13 рецептов с ключевыми словами;
- таблица всех 20 параметров;
- **шесть правил** для ассистента:
  1. пользовать инструмент, а не писать граф руками;
  2. двух цветов для большинства материалов мало — нужен третий;
  3. растяжение превращает шум в «фактуру» (дерево, штрихи);
  4. металлу нужен `metallic: 1`, иначе никакая шероховатость не спасёт;
  5. проверять результат в окне, а не в голове;
  6. процедурный материал всё равно надо запечь для игры.

⚠️ Скилл подхватывается **сам**, если в запросе есть подходящее слово:
«процедурный», «шум», «дерево» → `material-procedural` подставится
автоматически, без второго прохода к модели.

## 22.9. Итог главы

- Процедурный материал = **граф нод**, который лучше собирать кодом.
- Генератор: **описание → рецепт и числа → готовый граф**. Модель выбирает
  и подставляет, код собирает — без ошибок API.
- 13 рецептов, 5 узоров текстур, 20 настраиваемых параметров.
- Контекстное меню в шейдерном редакторе чинит **на месте проблемы** —
  без похода в панель AI.
