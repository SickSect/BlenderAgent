# Глава 15. Текстуры и пути: как проект переезжает и не ломается

> 📦 `src/blender_addon/textures.py`, `operators.py` (`gaa.pack_textures`,
> `gaa.fix_paths`, `gaa.texture_report`), `ui.py`, `i18n.py`,
> `tests/run_textures_check.py`

Глава 14 закончилась словами «файл текстуры потерян» и «текстура не
упакована» — двумя находками, которые доктор **умеет находить, но не умеет
чинить**. Эта глава — про то, как их закрыть.

---

## 15.1. Два способа потерять текстуры

### Способ 1: проект переехал

Текстуры лежат в папке `D:/textures/wood/`. Вы отправили `.blend` коллеге.
Коллега открывает — и видит серый материал.

Почему: внутри `.blend` хранится **не файл**, а **путь к файлу**. Путь может
быть абсолютным (`D:/textures/wood/albedo.png`) — тогда на другой машине он
не значит ничего.

### Способ 2: файл переехал

Вы переименовали папку, перенесли проект в другой каталог, отдали архив без
текстур. В `.blend` остался путь, а за ним — ничего.

---

## 15.2. Три средства защиты

| Средство | Что делает | Когда применять |
|---|---|---|
| **Упаковка** | текстура вшивается в сам `.blend` | после импорта текстур |
| **Относительные пути** | путь становится `//textures/albedo.png` | всегда |
| **Перелинковка** | потерянный файл находится по имени и подставляется | когда файл уже потерян |

### Упаковка

```python
image.pack()
```

Датаблок-изображение перестаёт быть «ссылкой на файл» и становится **частью
`.blend`**. Файл `packed_file` появляется, `image.source` остаётся `FILE`.

**Простыми словами:** упаковка — это «сложить все картинки в рюкзак». Обычно
картинка в сцене это *ссылка* на файл на диске: сцена лёгкая, но если папку с
картинками потерять или проект перенести на другой компьютер — картинок не
станет, и материалы останутся пустыми. После упаковки картинка лежит **внутри
самого `.blend`**: файл получается больше, но едет вместе со сценой и ничего не
теряется. Обратно: `textures.unpack_all` возвращает картинки на диск.

Когда это нужно:

- **передать проект** (заказчику, на другой компьютер, в сборку);
- **отдать `.blend` как единственный файл** — без папки с текстурами;
- **защитить проект** от случайной потери картинок.

Когда не нужно: если проект живёт на своём диске, картинки рядом, пути
относительные и всё под контролем — упаковка только раздувает файл.

Побочные эффекты, о которых надо знать:

- **размер `.blend` растёт** — ровно на размер текстур;
- **необратимо без распаковки** — но `image.unpack()` возвращает всё назад;
- **упакованная картинка не «пропадает»** — вот почему проверка «файл на
  месте» обязана смотреть на `packed_file` (глава 14).

Обратная операция:

```python
image.unpack(method="USE_ORIGINAL")   # вернуть файлы на диск
```

Методы: `REMOVE`, `USE_LOCAL`, `WRITE_LOCAL`, `USE_ORIGINAL`, `WRITE_ORIGINAL`.
Мы используем `USE_ORIGINAL` — картинка возвращается туда, откуда была
взята.

⚠️ Распаковка **пишет файлы на диск** и может их перезаписать. Поэтому
инструмент `textures.unpack_all` помечен как **разрушающий**: модель его не
запустит сама, а попросит вас нажать кнопку.

### Относительные пути

Путь, записанный в `.blend`, может быть:

| Вид | Пример | Значит |
|---|---|---|
| абсолютный | `D:/tex/albedo.png` | «лежит вот тут» — при переезде ломается |
| относительный | `//textures/albedo.png` | «рядом с файлом `.blend`» — переезжает вместе |

Blender **сам** переводит внешние пути в относительные при сохранении (опция
«Relative Paths» в настройках включена по умолчанию). Но:

- путь, записанный **скриптом**, остаётся абсолютным;
- если опцию выключили в настройках — останется абсолютным;
- путь, заданный **до первого сохранения** файла, тоже абсолютный.

Поэтому кнопка «Пути» нужна как страховка. Код:

```python
relative = bpy.path.relpath(path, start=bpy.data.filepath)
image.filepath = relative
```

⚠️ **Ловушка `bpy.path.relpath`.** Функция ждёт **путь к файлу** базы, а не
к папке: Blender берёт *родителя* от `start` и считает путь относительно
него. Если передать папку, всё сместится на уровень выше:

```python
bpy.path.relpath(path, start=os.path.dirname(blend_path))   # ✗ неверно
bpy.path.relpath(path, start=blend_path)                    # ✓ верно
```

Эту ошибку поймал тест `run_textures_check.py`.

⚠️ **Ловушка `os.path.isabs` на Windows.** Путь `//textures/albedo.png` —
относительный для Blender, но `os.path.isabs` на Windows считает его
абсолютным (двойной слэш читается как UNC-путь). Поэтому «абсолютность» надо
определять вручную:

```python
def _is_absolute_path(path):
    if not path:
        return False
    if path.startswith("//"):     # относительный для Blender
        return False
    return os.path.isabs(path)
```

## 15.3. Перелинковка: найти потерянное

Когда файл уже потерян, нужно его **найти**. Единственный надёжный признак —
имя: `Wood_BaseColor.png` должен остаться `Wood_BaseColor.png`.

Стратегия поиска (ближние — первыми):

1. папки, которые назвал пользователь;
2. папка самого `.blend` (несколько уровней вглубь);
3. папка, где файл **раньше лежал** (если она ещё существует).

```python
def relink(search_paths=None):
    roots = _search_roots(search_paths)
    index = {}
    for root in roots:
        for path in _walk(root):                 # глубина ≤ 3
            index.setdefault(os.path.basename(path).lower(), path)

    for image in file_images():
        if not is_missing(image):
            continue
        found = index.get(os.path.basename(image.filepath).lower())
        if found:
            image.filepath = found
```

Поиск **ограничен**: глубина 3 уровня и максимум 20 000 файлов. Иначе
кнопка «Пути» на проекте с тысячами файлов подвисла бы на минуту.

⚠️ Поиск идёт **по имени файла**, а не по содержимому. Если в проекте два
файла с одинаковым именем в разных папках, победит первый найденный. Это
осознанный компромисс: сравнивать по содержимому (хеш) — дорого и не всегда
нужно, потому что в 99% случаев имя и есть идентификатор.

## 15.4. Цветовое пространство: граф важнее имени

Текстуры `textures.fix_colorspace` ставит цветовое пространство по **роли
карты**. Но роль определяется двумя способами, и они могут противоречить
друг другу:

| Ситуация | Что решает |
|---|---|
| картинка **в графе** | **сокет**: подключена в `Roughness` → значит данные → `Non-Color` |
| картинка **вне графа** | **имя файла**: `roughness.png` → `Non-Color` |

Правило простое: **граф всегда важнее имени**. Если `roughness.png` подключена
в `Base Color` — это альбедо, и какой бы файл это ни назывался.

```python
def expected_colorspace(image):
    sockets = image_sockets(image)
    if sockets:
        if any(name in api.DATA_SOCKETS for name in sockets):
            return "Non-Color"
        return "sRGB"
    role = materials.detect_role(image.name)
    ...
```

Это ровно тот случай, где «умная эвристика по имени» проиграла бы факту из
графа. Имя — гипотеза, сокет — факт.

## 15.5. Отчёт по текстурам

Отчёт — это не украшение, а **диагностика**:

```
Текстуры (5):
- Wood_BaseColor.png  1024x1024  sRGB  [не упакована]  //textures/Wood_BaseColor.png
- Wood_Roughness.png  1024x1024  sRGB  [space should be Non-Color]  //textures/...
- Metal_Diffuse.png   0x0  sRGB  [MISSING]  D:/textures/does_not_exist_Metal_Diffuse.png
```

Что видно сразу:

- **размер** — `0x0` означает, что картинка не загрузилась (файла нет);
- **цветовое пространство** и подсказка, каким оно должно быть;
- **упакована ли**;
- **путь** — относительный или абсолютный.

⚠️ Один и тот же текст читают и человек, и модель. Для человека — язык
интерфейса, для модели — **английский**. Поэтому `i18n.T` получил
необязательный параметр `lang`:

```python
finding.text()        # язык интерфейса
finding.text("en")    # для модели
```

## 15.6. Инструменты и кнопки

Шесть инструментов, каждое с одной кнопкой или без неё:

| Инструмент | Кнопка | Разрушает |
|---|---|---|
| `textures.pack_all` | **Упаковать** | нет |
| `textures.unpack_all` | — | **да** |
| `textures.make_relative` | **Пути** | нет |
| `textures.relink` | **Пути** | нет |
| `textures.fix_colorspace` | — | нет |
| `textures.report` | **Отчёт** | нет |

Кнопка «Пути» делает две вещи сразу: относительные пути **и** перелинковку
потерянных. Это самая частая комбинация: переехал проект — и сразу обе
проблемы.

## 15.7. Как это проверяется

📦 `tests/run_textures_check.py`. Сцена собирается с тремя состояниями
текстуры: нормальной, с абсолютным путём и с потерянным файлом.

```
== the report
ok   the report marks the lost file
== colour spaces
ok   a colour map keeps sRGB (the graph decides)
ok   a data map by file name is set to Non-Color
== packing
ok   the good texture was packed
ok   packing twice changes nothing
== paths
ok   the absolute path was made relative
ok   a relative path is left alone
ok   and can be made absolute again
== relinking a lost file
ok   the lost file is found
ok   the lost texture was relinked
== the tools
ok   unpacking is destructive (it writes files)
ok   packing is not destructive (it can be undone)
RESULT: OK
```

⚠️ Тест на «абсолютный путь» пришлось делать **после сохранения** `.blend`:
Blender при сохранении сам переводит внешние пути в относительные. Чтобы
воспроизвести абсолютный путь, его надо задать явно — и это само по себе
полезно знать.

## 15.8. Итог главы

- Текстуры — это **ссылки**, а не данные: путь внутри `.blend` может
  перестать работать в любой момент.
- Три защиты: **упаковка** (данные едут вместе с файлом), **относительные
  пути** (файл едет вместе с проектом), **перелинковка** (файл нашёлся).
- `bpy.path.relpath` ждёт **путь к файлу** базы, а не к папке.
- `os.path.isabs` на Windows считает `//путь` абсолютным — «абсолютность» для
  Blender надо проверять руками.
- Цветовое пространство определяет **граф**, а не имя файла. Имя — гипотеза,
  сокет — факт.
- Распаковка пишет на диск → она **разрушающая**, и модель её не запускает.
- Один и тот же отчёт читают и человек, и модель: `i18n.T(key, lang="en")`.
