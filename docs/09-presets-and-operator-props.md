# Глава 9. Кнопки-действия и параметры операторов: пресеты материалов

Глава 8 открывала редакторы. Эта — про то, как кнопка может **нести в себе
значение** и не выполнять ничего разрушительного. Повод: в чат добавлен блок
«Пресеты материалов» — пять кнопок, которые подставляют готовый запрос в поле
ввода:

```
┌ Пресеты материалов ────────────┐
│ [ Матовый ]      [ Металл ]    │
│ [ Стекло ]       [ Эмиссия ]   │
│ [ PBR ]                        │
└────────────────────────────────┘
```

📦 `i18n.py` (`preset.*`), `operators.py` (`GAA_OT_use_preset`), `ui.py`
(`_PRESET_IDS` и отрисовка сетки).

---

## 9.1 Идея: одна кнопка = оператор + параметр

Пять пресетов — это одно **действие** («подставить в поле ввода») с пятью
**значениями**. Дублировать пять операторов незачем: у оператора в Blender можно
объявить **своё свойство** (аннотацию типа) — и оно станет параметром.

📦 `GAA_OT_use_preset`:

```python
class GAA_OT_use_preset(bpy.types.Operator):
    """Подставить готовый запрос в поле ввода чата"""

    bl_idname = "gaa.use_preset"
    bl_label = "Material preset"
    bl_options = {"REGISTER"}

    preset: StringProperty(default="matte")

    def execute(self, context):
        key = "preset.%s.text" % self.preset
        ...
        context.window_manager.gaa_input = i18n.T(key)
        return {"FINISHED"}
```

Разберём ключевые моменты.

### Свойство оператора — это часть его RNA

Строка `preset: StringProperty(default="matte")` в теле класса регистрируется как
**свойство оператора**. У него появляется:

- поле в F3-панели «Adjust Last Operation» (нижний левый угол) — можно менять и
  **повторять** операцию;
- возможность задать значение из кода до вызова (см. §9.2);
- автоматическое «запоминание» последнего значения между вызовами.

⚠️ Именно поэтому аннотация пишется **в классе**, а не в `__init__`: Blender
собирает RNA по аннотациям при `register_class`. Это тот же механизм, что у
свойств `Scene`/`Object` из главы 1, только теперь мы добавляем своё свойство
оператору.

### Зачем отдельный `execute`, если можно было сразу в draw?

Отрисовка (`draw`) должна **только рисовать**: она вызывается десятки раз в
секунду, ей нельзя менять состояние. Всё, что меняет данные, — это `execute`
(см. главу 5 про панели и операторы). Кнопка в UI лишь *запускает* оператор.

### `bl_options = {"REGISTER"}` — и почему не `UNDO`

Здесь `REGISTER` без `UNDO`. Разница:

| Опция | Что даёт |
|---|---|
| `REGISTER` | оператор «запоминается» для повтора / Adjust Last Operation |
| `UNDO` | результат попадает в стек `Ctrl+Z` |

`use_preset` **не меняет сцену** — он пишет в поле ввода чата. Добавлять его в
Undo-стек бессмысленно (отменять нечего). А вот `gaa.run_code` из главы 4 —
`UNDO`, потому что меняет сцену. **Правило: `UNDO` — только для операторов,
меняющих данные Blender.**

## 9.2 Как кнопка передаёт значение

📦 `ui.py`, внутри общей функции `draw_chat`:

```python
_PRESET_IDS = ("matte", "metal", "glass", "emission", "pbr")

...

box = layout.box()
box.label(text=i18n.T("presets.title"), icon="PRESET")
grid = box.grid_flow(row_major=True, columns=2, even_columns=True, align=True)
for preset_id in _PRESET_IDS:
    props = grid.operator("gaa.use_preset", text=i18n.T("preset." + preset_id))
    props.preset = preset_id
```

Смотри на последние две строки:

- `grid.operator("gaa.use_preset", text=...)` **рисует** кнопку и **возвращает
  объект со свойствами оператора** (`OperatorProperties`);
- `props.preset = preset_id` — задаёт параметр **до** нажатия. При клике Blender
  вызовет `execute` уже с этим значением в `self.preset`.

Так одна кнопка в коде превращается в пять разных, не плодя пять операторов.

### Устройство сетки

- `layout.box()` — рамка-группа (визуально «коробка»);
- `box.label(text=..., icon="PRESET")` — заголовок с иконкой;
- `grid_flow(row_major=True, columns=2, ...)` — раскладка **сеткой**; сайдбар узкий,
  поэтому две колонки компактнее одной колонки из пяти кнопок.

Проверить доступные параметры `grid_flow` из самого Blender можно так:

```python
import bpy
f = bpy.types.UILayout.bl_rna.functions["grid_flow"]
print([p.identifier for p in f.parameters])
# ['row_major', 'columns', 'even_columns', 'even_rows', 'align', 'layout']
```

Это общий приём: **любой** метод рисования (`row`, `column`, `box`, `grid_flow`,
`operator`, `prop`…) можно изучить через `bl_rna.functions` — не нужно угадывать
параметры.

## 9.3 Почему `StringProperty`, а не `EnumProperty`

«Правильнее» на первый взгляд — сделать `EnumProperty` с пятью пунктами. Но у
`i18n.py` есть известное ограничение (см. её docstring): **имена пунктов enum и
подсказки свойств запекаются в RNA один раз при регистрации**. После смены языка
они не обновятся без перерегистрации.

Поэтому:

- **значение** (`preset`) — это `StringProperty` (обычная строка, без имена);
- **видимую подпись** кнопки рисует `text=i18n.T("preset." + preset_id)` — то есть
  перевод берётся **в момент отрисовки** и всегда актуален;
- **текст запроса** оператор достаёт из i18n **в момент вызова**.

```python
key = "preset.%s.text" % self.preset          # напр. "preset.metal.text"
lang = i18n.get_lang()
if key not in i18n.STRINGS[lang] and key not in i18n.STRINGS[i18n.DEFAULT_LANG]:
    return {"CANCELLED"}                       # неизвестный пресет — тихо выходим
context.window_manager.gaa_input = i18n.T(key)
```

Guard на `key not in STRINGS[...]` нужен на случай, если имя пресета пришло не из
кнопки (например, из скрипта): лучше ничего не делать, чем подставить в поле
ввода строку-ключ вида `preset.foo.text`.

⚠️ Общее правило из этого: **в UI-строках не полагайся на RNA-запекшиеся имена**
(enum items, `bl_label`), если нужна смена языка «на лету». Динамический текст
рисуется через `i18n.T()` в `draw`.

## 9.4 Текст пресета — это код, который напишет модель

Пресет — не просто строка: это **задание для модели**, по которому она сгенерирует
bpy-код. Значит, неточность в тексте пресета превращается в баг в чужом коде.

Реальный случай из этого аддона. Пресет «Стекло» просил «Transmission 1.0» — и
модель писала ровно это:

```python
bsdf.inputs["Transmission"].default_value = 1.0
```

Что падало с ошибкой:

```
KeyError: 'bpy_prop_collection[key]: key "Transmission" not found'
```

Причина: в Blender 4.0 вход переименовали — теперь он `Transmission Weight`
(вместе с ним: `Specular` → `Specular IOR Level`, `Clearcoat` → `Coat Weight`,
`Emission` → `Emission Color` + `Emission Strength`). Матовый, металл и эмиссия
работали, потому что их сокеты не переименовывали, — падало только стекло.

Как это нашли: прогнали код каждого пресета на стартовом кубе (в `--background`)
и увидели `KeyError` только на стекле. Отсюда два вывода:

1. **Промпт проверяют как код.** Если текст расходится с реальным API, ломается не
   он, а сгенерированный скрипт — и искать причину будешь не там.
2. **Модель нужно вооружить актуальными именами.** В системный промпт добавлен
   список входов Principled BSDF для 4.x/5.x с прямым запретом имён из 2.8–3.x, а
   в снимок сцены — значение Transmission (чтобы модель видела уже сделанное
   стекло и не переделывала его).

Исправление задело три файла:

```python
# i18n.py — пресет говорит на языке текущей версии Blender
"preset.glass.text": "... Principled BSDF, Transmission Weight 1.0, Roughness 0.0, IOR 1.45 ..."

# prompts.py — системный промпт перечисляет имена сокетов 4.x/5.x
# snapshot.py — снимок показывает transmission, если он не нулевой
```

⚠️ **Правило:** имена сокетов в коде и в промптах — версионно-зависимые данные.
Держи их в одном месте и обновляй при смене мажорной версии Blender.

## 9.5 Куда попадает текст: `WindowManager.gaa_input`

Оператор не «печатает» в чат, а кладёт строку в **свойство окна**:

```python
context.window_manager.gaa_input = i18n.T(key)
```

`gaa_input` — то самое `WindowManager`-свойство, которое мы объявили в `ui.py`
(глава 5) и рисуем как поле ввода через `layout.prop(wm, "gaa_input", ...)`.
Поэтому цепочка получается такой:

```
кнопка → execute → wm.gaa_input = "текст"
                          ↓ (следующий redraw)
        поле ввода показывает текст    ← пользователь может поправить
                          ↓
        кнопка "Отправить" читает wm.gaa_input (gaa.send, глава 3)
```

Ключевое: пресет — это **подсказка**, а не мгновенная отправка. Пользователь может
уточнить путь к текстурам, размеры и т.п. перед нажатием «Отправить».

## 9.6 Альтернатива: всплывающее меню

Если пресетов станет много (10+), сетка кнопок займёт пол-сайдбара. Тогда их
прячут в меню:

```python
def _draw_presets(menu, context):
    for preset_id in _PRESET_IDS:
        op = menu.operator("gaa.use_preset", text=i18n.T("preset." + preset_id))
        op.preset = preset_id

# ... а кнопка одна:
def execute(self, context):
    context.window_manager.popup_menu(_draw_presets, title=i18n.T("presets.title"))
    return {"FINISHED"}
```

Функция рисования меню принимает `(menu, context)`, а элементы — те же операторы.
Мы выбрали сетку: пресетов пять, и один клик удобнее двух.

## 9.8 Шпаргалка терминов

| Термин | Что это |
|---|---|
| **свойство оператора** | аннотация вида `preset: StringProperty(...)` в классе |
| **OperatorProperties** | объект, который возвращает `layout.operator(...)`, чтобы задать параметры до вызова |
| **`REGISTER` / `UNDO`** | запомнить оператор / положить результат в стек отмены |
| **`EnumProperty` vs `StringProperty`** | первое запекает имена в RNA (плохо для i18n), второе — нет |
| **`grid_flow`** | раскладка кнопок сеткой |
| **`wm.gaa_input`** | свойство окна, общее состояние поля ввода чата |

## 9.9 Итог главы

- Один оператор + **свойство-параметр** заменяет пять почти одинаковых операторов.
- Значение кнопки задаётся из `draw` через `props.preset = ...` в момент отрисовки.
- Тексты берутся из `i18n.T()` на лету — никаких RNA-запекшихся имён.
- Пресет **не отправляет** запрос, а лишь заполняет поле ввода — пользователь
  остаётся в контуре управления.

На этом шаг B закрыт: кнопки редакторов + пресеты. Дальше — по роадмапу
(например, быстрые действия с нодами или пресеты PBR-наборов).
