# Гайд по возможностям ассистента

> Что аддон умеет, как это пользовать и что он **не** умеет.
> Практическое руководство: минимум теории, максимум примеров.

Ассистент — это **надстройка над Blender**, а не замена Blender. Он умеет три
вещи, и важно понимать, чем они отличаются:

| Слой | Что это | Скорость | Надёжность |
|---|---|---|---|
| **Знание** | рецепты: как правильно делать стекло, ORM, цвета | модель уже знает | зависит от модели |
| **Действие** | кнопки и инструменты: доктор, починка, упаковка | **мгновенно** | всегда |
| **Совет** | ответ на вопрос текстом | 1–5 минут на CPU | зависит от модели |

⚠️ **Правило номер один.** Если задачу можно решить кнопкой — решайте кнопкой.
Она работает мгновенно и всегда. Чат с локальной моделью на CPU отвечает
минутами и иногда ошибается.

---

## Часть 1. Три минуты после установки

Сделайте это один раз — и проект начнёт «ездить» без потерь.

| Шаг | Где | Зачем |
|---|---|---|
| 1 | **AI → Текстуры → Упаковать** | текстуры вшиваются в `.blend` — проект больше не зависит от папки на диске |
| 2 | **AI → Текстуры → Пути** | пути становятся относительными, потерянные файлы находятся сами |
| 3 | **AI → Доктор материалов** | покажет, что в материалах сломано |
| 4 | **AI → Доктор → Починить** | починит то, что чинится безопасно |
| 5 | **AI → Импорт и экспорт → Проверка экспорта** | покажет, что сломается при передаче проекта |
| 6 | **Ctrl+S** | сохранить файл |

Повторять шаги 1–2 нужно после каждого импорта текстур.

А если текстуры только что приехали в новой папке — сразу **AI → Импорт и
экспорт → Импорт из папки**: это все пять шагов разом.

## Часть 2. Кнопки панели AI — полный обзор

Панель **AI** есть в трёх местах: в 3D-вьюпорте (**N** → вкладка AI), в
редакторе шейдеров и в редакторе изображений. Плюс всплывающее окно
(**Ctrl+Alt+A**) — оно шире и удобнее.

### Пресеты материалов

| Кнопка | Что делает |
|---|---|
| **Матовый** | подставляет в чат запрос на матовый материал |
| **Металл** | …на металлический |
| **Стекло** | …на стеклянный |
| **Эмиссия** | …на светящийся |
| **PBR** | …на PBR из папки (попросит путь) |
| **PBR из папки** | **не спрашивает модель** — сам собирает материал из папки с текстурами |

Пресеты — это *заготовки вопросов*. Их можно править перед отправкой.

> 💡 «PBR из папки» — единственная кнопка, которая работает **полностью без
> модели**. Отвечает за секунду.

### Доктор материалов

| Кнопка | Что делает |
|---|---|
| **Доктор** | находит ошибки в материалах, отчёт — в панели чата |
| **Починить** | чинит безопасные ошибки; один `Ctrl+Z` отменяет всё |

### Текстуры

| Кнопка | Что делает |
|---|---|
| **Упаковать** | вшивает все файловые текстуры в `.blend` |
| **Пути** | абсолютные пути → относительные; потерянные файлы ищутся по имени |
| **Отчёт** | список всех текстур: размер, цветовое пространство, упакована ли, где файл |

### Импорт и экспорт

| Кнопка | Что делает |
|---|---|
| **Импорт из папки** | **весь процесс одним кликом**: сканирует папку с текстурами → собирает PBR-материал → назначает его выделению → упаковывает текстуры в `.blend` → проверяет, готов ли проект к передаче. Отчёт — в панели чата |
| **Проверка экспорта** | что сломается при передаче: потерянные файлы, неупакованные текстуры, меши без UV, шейдеры, которые glTF/FBX не переносят, слишком крупные текстуры |
| **GLB** / **FBX** | **последняя миля**: пишет выделенное в файл, который открывает движок. Оси как ждёт движок (+Y), модификаторы применены, текстуры скопированы рядом. Перед экспортом идёт проверка готовности: если она нашла ошибки — кнопка всё равно экспортирует, но пишет их в отчёт |

> 💡 «Импорт из папки» — самая «толстая» кнопка аддона: пять операций, один
> клик, один `Ctrl+Z` на откат.

> 📦 Имя файла — имя сцены (или объекта, если выделен один). Папку выбираешь
> в диалоге, который открывается по кнопке. Ассистент может сделать то же
> само: `export.glb` / `export.fbx` — но там проверка готовности **блокирует**
> экспорт, если нашла ошибки: сначала починить, потом отдать.

### UV

| Кнопка | Что делает |
|---|---|
| **Развернуть** | швы по углу → развёртка → минимизация искажений → укладка островов с зазором. Работает на выделенных объектах (или на всей сцене, если ничего не выбрано) |
| **Плотность** | выравнивает плотность текселей по всем островам объекта — текстура становится одинаково резкой везде |

#### Симметричная развёртка

Текстура **вдвое меньше**: рисуешь половину, вторая получается зеркалом.

```
Сделай симметричную развёртку персонажа
```

Аддон отметит швы по плоскости симметрии, развернёт модель и скопирует UV
второй половины первой.

⚠️ **Такой объект нельзя класть в атлас** — симметричная раскладка это
перекрытие островов **по замыслу**. Ему нужна своя текстура.

Ось симметрии — в настройках сцены (X / Y / Z) или параметром на вызов.

#### Развёртка по своим швам

Авто-швы по углу — это потолок. На персонаже нужно резать **там, где скажешь**,
и шов должен идти **скрытым**. Поэтому:

| Что | Как |
|---|---|
| Развернуть **только по своим швам** | галочка «Только по своим швам» в панели AI |
| Ручные швы **не затираются** | автоматические швы только добавляются, никогда не удаляют |
| **Разрез по высоте** (рукава, сапоги, пояса) | `Разрез по высоте 1.2` — меш реально режется, новые рёбра становятся швами |

```
Поставь разрез по высоте 1.2 на персонажа и разверни его по своим швам
```
| **Атлас** | собирает **общий атлас** из островов выделенных объектов: укладка с зазором, паддинг, единая плотность |
| **UV-комплект** | выгружает на диск раскладку UV + манифест + копию текстуры — чтобы рисовать в Aseprite или Krita |
| **Импорт атласа** | кладёт нарисованный PNG в Base Color материала активного объекта |
| **Проверить UV** | плотность текселей, перекрытия, выход за [0,1], искажение — по каждому объекту |

> 💡 Плотность текселей (px/м) — единственная проблема UV, **невидимая в
> редакторе и очень заметная в игре**: одна текстура на двух объектах разного
> размера выглядит по-разному.

#### Настройки развёртки — три уровня управления

**1. Настройки проекта** (в панели AI — ползунок «Швы по углу», остальное — в
**Scene Properties → Asset Assistant → UV**):

| Параметр | По умолчанию | Что значит |
|---|---|---|
| **Швы по углу** | 40° | рёбра, угол между гранями которых больше, становятся швами |
| **Метод развёртки** | По углу (`ANGLE_BASED`) | или конформная / проекционная |
| **Зазор между островами** | 0.02 | пустое расстояние между островами (для мипмапов) |
| **Минимизировать искажения** | вкл | прогон `minimize_stretch` после развёртки |
| **Учитывать острые рёбра** | вкл | помеченные sharp рёбра тоже становятся швами |
| **Smart UV для гладких объектов** | вкл | если швов не получилось (гладкая замкнутая поверхность) — автоматическая развёртка |
| **Плотность текселей** | 16 px/м | целевая плотность (используется при выравнивании) |
| **Размер атласа** | 2048 | сторона атласа в пикселях |

⚠️ Настройки живут **в сцене**, а не в настройках аддона: у гейм-проекта и у
архвиз-проекта они разные, и переключать их вручную перед каждым проектом —
лишнее.

**2. Переопределение на один вызов** — через ассистента:

```
Разверни Cube с углами швов 25 градусов и зазором 0.01
```

**3. Ассистент сам видит текущие настройки** — они попадают в снимок сцены
строкой `UV settings: seams at 40 deg, method ANGLE_BASED, gap 0.020, target
density 16 px/m, atlas 2048`, поэтому он не выдумывает числа.

### Бейкинг

| Кнопка | Что делает |
|---|---|
| **Запечь** | превращает процедурный материал активного объекта в текстуры: albedo и карту нормалей. Картинки остаются в файле (их можно упаковать или сохранить на диск) |
| **ORM-карта** | три карты (AO + шероховатость + металл) в одной — того формата, который ждут glTF и игровые движки |
| **Превью** | маленькая картинка объекта с материалом, сразу открывается в Image Editor; в имени — дата и время, чтобы превью не путались |
| **Высота → нормали** | делает карту нормалей из карты высот — как xNormal, но внутри Blender. Разница высот превращается в наклон поверхности |

Что для этого нужно и что делает аддон:

| Требование | Кто обеспечивает |
|---|---|
| Движок Cycles | аддон переключает на время запекания и возвращает обратно |
| UV без перекрытий | сначала «Атлас» или «Проверить UV» |
| Картинки-таргеты | аддон создаёт их сам (правильного размера, цветового пространства и float buffer) |
| Узел-таргет | аддон создаёт и **убирает за собой** — в материале не остаётся мусора |

> ⚠️ Бейкинг занимает **главный поток** — на большой сцене Blender подвиснет на
> минуты. Это нормально для запекания.

> 💡 **Нормали будут плоскими**, если в материале нет источника высоты (Displacement
> или Bump). Аддон предупредит об этом заранее.

### Процедурные материалы

| Кнопка | Что делает |
|---|---|
| **Процедурный** | собирает процедурный материал по описанию: «тёмное дерево» → готовый граф нод |

Ассистент тоже умеет:

```
Сделай процедурный деревянный материал
```

```
Сделай ржавый металл: оранжево-коричневый, очень шершавый, с сильным рельефом
```

```
Покажи, какие есть процедурные рецепты
```

> 💡 Почему это работает: **модель понимает описание и подставляет числа, а
> граф собирает код**. Поэтому результат всегда корректный и одинаковый — в
> отличие от кода, написанного моделью с нуля.

> 💡 Ассистент знает о процедурных материалах из **скилла**
> `material-procedural`: он подхватывается сам по слову «процедурный» или
> «шум», и его примеры кода проверяются на живом Blender.

### Контекстное меню в шейдерном редакторе

**Правая кнопка по узлу Image Texture** в Shader Editor:

```
Asset Assistant
   Починить цветовое пространство
   Упаковать в .blend
   Сделать путь относительным
   ─────────────────────────────
   Подключить в Base Color / Roughness / Normal
```

Пункты появляются **только** для Image Texture и **дополняют** штатное меню
Blender, а не заменяют его.

> 📖 Подробнее — в [`22-procedural-and-menu.md`](22-procedural-and-menu.md).

### Переходы по редакторам

| Кнопка | Что делает |
|---|---|
| **Shader Editor** | открывает шейдерный редактор на материале активного объекта |
| **Image Editor** | открывает картинку материала в редакторе изображений |

### Массовые операции

| Кнопка | Что делает |
|---|---|
| **Назначить выделению** | назначает материал активного объекта **всем выделенным** объектам |
| **Кто использует** | показывает объекты, слоты и число граней, где лежит этот материал |

> 💡 «Назначить выделению» — самая частая операция в гейм-арте: слепил
> материал, выделил 80 объектов, нажал кнопку. Второй слот при этом
> **заменяется**, а не добавляется.

## Часть 3. Что ассистент видит

Каждый вопрос уходит в модель **вместе со снимком сцены** — текстом, который
описывает текущее состояние Blender. Это единственный способ, которым модель
«видит» ваш проект.

### Что входит в снимок

| Раздел | Что там |
|---|---|
| Версия и сцена | версия Blender, движок рендера, fps, коллекции |
| Объекты | имя, тип, положение, поворот, размер, число полигонов, UV-слои, материалы, модификаторы |
| Выделение и активный объект | что выбрано прямо сейчас |
| Материалы | список материалов файла: узлы, значения Principled, текстуры |
| Изображения | размер, цветовое пространство, упакована ли, **файл на месте ли** |
| **Material in focus** | подробный разбор того материала, который вы открыли в шейдерном редакторе: все ноды, все связи, текстуры, кто использует |
| **Shader editor** | какой узел активен, какие выделены |
| **Image editor** | какая текстура открыта |
| **Problems** | найденные проблемы (см. доктор) |

### Фокус — снимок «смотрит» туда, куда смотрите вы

| Где вы работаете | Что раскрывается подробно | Что обрезается |
|---|---|---|
| **Shader Editor** | материал, который открыт | список объектов и материалов укорачивается |
| **Image Editor** | текстура | то же |
| **3D-вьюпорт** | сцена целиком | ничего |

### Можно ли это выключить

**Edit → Preferences → Add-ons → Asset Assistant → «Отправлять снимок сцены»**.
Выключите — и модель станет «слепой»: перестанет видеть объекты, материалы и
проблемы. Это же лучший способ **проверить, что ассистент не выдумывает**.

## Часть 4. Что ассистент умеет (инструменты)

Инструменты — это **готовые действия** аддона. Модель может вызвать их сама
и получить отчёт в ответ. Все они дублируются кнопками в панели.

| Инструмент | Что делает | Разрушает? |
|---|---|---|
| `material.audit` | находит проблемы в материалах | нет |
| `material.fix` | чинит безопасные проблемы | нет |
| `material.build_from_folder` | собирает PBR-материал из папки | нет |
| `textures.pack_all` | упаковывает текстуры в `.blend` | нет |
| `textures.unpack_all` | распаковывает текстуры на диск | **да** |
| `textures.make_relative` | абсолютные пути → относительные | нет |
| `textures.relink` | находит потерянные файлы по имени | нет |
| `textures.fix_colorspace` | чинит цветовые пространства по роли карты | нет |
| `textures.report` | отчёт по всем текстурам | нет |
| `materials.assign_to_selection` | назначает материал всему выделению | нет |
| `materials.replace_everywhere` | меняет материал во всей сцене | нет |
| `materials.find_users` | кто использует материал | нет |
| `materials.make_instance` | делает объекты инстансами (общий меш) | нет |
| `materials.make_single_user` | разрывает общий меш | нет |
| `materials.make_variant` | делает оттенок-вариант материала | нет |
| `materials.cleanup_orphans` | удаляет неиспользуемые материалы и картинки | **да** |
| `project.import_textures` | весь процесс: папка → материал → назначение → упаковка → проверка | нет |
| `export.check` | проверка готовности проекта к передаче | нет |
| `uv.audit` | проверка развёртки: плотность, перекрытия, выход за границы | нет |
| `uv.unwrap` | развёртка: швы по углу → unwrap → искажения → укладка | нет |
| `uv.mark_seams` | ставит швы по углу, по высоте (разрез) или снимает все | нет |
| `uv.symmetric` | симметричная развёртка: текстура вдвое меньше | нет |
| `uv.match_density` | выравнивает плотность текселей по островам объекта | нет |
| `uv.build_atlas` | общий атлас из островов нескольких объектов | нет |
| `uv.unwrap_own` | развёртка **без** атласа — каждый остров на своём месте | нет |
| `uv.export_kit` | UV-комплект: раскладка PNG + манифест + копия текстуры | нет |
| `uv.import_atlas` | кладёт нарисованный атлас в Base Color материала | нет |
| `bake.maps` | запекает процедурный материал в текстуры (albedo, normal, roughness, AO) | нет |
| `bake.check` | проверяет, можно ли запечь объект | нет |
| `bake.normal_from_height` | строит карту нормалей из карты высот | нет |
| `bake.atlas` | запекает несколько объектов в один общий атлас | нет |
| `bake.replace` | заменяет процедурный материал на запечённый | нет |
| `procedural.list` | список готовых процедурных рецептов | нет |
| `procedural.build` | собирает процедурный материал по рецепту и параметрам | нет |
| `tools.list` | список всех доступных инструментов | нет |
| `tools.history` | что ассистент уже сделал за этот разговор | нет |

**«Разрушает»** = модель не выполнит это сама. Вместо этого появится блок с
кнопками **«Выполнить»** и **«Отмена»** прямо в чате — и ход останется
открытым: после твоего клика инструмент выполнится, а ассистент получит
отчёт и продолжит разговор.

В блоке подтверждения видно **что именно исчезнет**:

```
⚠ Подтвердите инструмент «Clean up orphans»
Delete the materials and images that nothing uses.
Будет удалено: 3 material(s): OldWood, OldMetal, OldPlastic
[✓ Выполнить]  [✕ Отмена]
```

А `tools.history` отвечает на вопрос «а что ты вообще сделал?»:

```
12 tool call(s) so far:
- material.audit (ok): Audited the scene: 2 errors, 2 warnings, 4 notes.
- uv.build_atlas (ok): Atlas: 12 island(s) from 2 object(s), 43% of a 2048px texture
- materials.cleanup_orphans (not done): The user declined the tool 'Clean up orphans'.
```

### Как модель вызывает инструмент

Внутри ответа ассистента появляется блок:

````
```tool
material.audit
```
````

Аддон выполняет его и приклеивает результат обратно в контекст. Дальше модель
продолжает работу уже **с фактами**, а не с догадками.

## Часть 5. Что ассистент знает (скиллы)

Скиллы — это **проверенные рецепты**: точное имя сокета, правильный порядок
нод, различия версий Blender. Каждый скилл — файл с кодом, который
**исполняется на живом Blender** в тестах, поэтому он не может разойтись с
API.

| Скилл | Про что |
|---|---|
| `material-principled` | точные имена входов Principled BSDF в 4.x/5.x |
| `material-colorspace` | какая карта в `sRGB`, а какая в `Non-Color` |
| `material-pbr-maps` | как разложить albedo / roughness / metallic / normal по сокетам |
| `material-normal-map` | узел Normal Map, сила, ловушка DirectX/OpenGL |
| `material-orm-packed` | разборка упакованной карты ORM: R=AO, G=Rough, B=Metal |
| `material-glass` | Transmission Weight, IOR, настройки EEVEE |
| `material-metal-roughness` | значения металла и шероховатости, почему металл чёрный |

### Как это работает

**Автоматически.** Если в вашем вопросе есть подходящее слово, нужная
инструкция подставится сама:

> «сделай **стеклянный** материал» → в панели мелькнёт
> `Читаю инструкцию: material-glass…` → модель сразу ответит правильно.

**По запросу.** Модель сама может попросить инструкцию — тогда будет второй
проход (задержка на один запрос).

### Круговорот с другими программами

Полный цикл «Blender → Aseprite/Krita → Blender»:

```
1. Выдели объекты → AI → UV → Атлас
2. AI → UV → UV-комплект          ← на диск появится папка uv_kit
3. Открой layout.png в Aseprite или Krita и нарисуй атлас
4. Сохрани как PNG
5. AI → UV → Импорт атласа → выбери свой PNG
```

Что в папке `uv_kit`:

| Файл | Что это |
|---|---|
| `layout.png` | раскладка UV, того же размера, что атлас. Открыть как направляющий слой и рисовать поверх |
| `manifest.json` | размер атласа, зазор, плотность, список объектов и текстур. Через месяц — единственное напоминание, как всё было устроено |
| `albedo_<объект>.png` | копия текущей текстуры, если она была |

> 💡 **Почему это работает без рассинхрона:** импорт **не трогает UV**.
> Пока координаты не менялись, пиксель картинки = пиксель текстуры. Поэтому
> нарисованное ложится ровно туда, куда показала раскладка.

> 💡 **Чтобы открывать картинки сразу в Aseprite/Krita:** пропиши путь к
> программе в **Preferences → File Paths → Image Editor**. Тогда в Image Editor
> появится *External Edit*.

## Часть 7. Чего ассистент НЕ умеет

Чтобы не ждать от него невозможного:

| Не умеет | Почему |
|---|---|
| видеть картинку | модель получает текст, не пиксели |
| редактировать UV | для этого нужен контекст вьюпорта (в работе) |
| запекать текстуры | это отдельная большая тема (в плане) |
| работать без снимка сцены | выключите снимок — и модель ослепнет |
| отвечать быстро | локальная модель на CPU: 1–5 минут |
| гарантировать правильный код | код **предлагается**, а не выполняется — читайте перед запуском |

⚠️ **Про код.** Ответ может содержать блок ```python и кнопку «Выполнить
код». Код выполняется в вашей сцене. Перед этим **сохраните файл**: отмена
(`Ctrl+Z`) работает, но падение Blender отмены не отменяет.

## Часть 8. Если что-то не работает

| Симптом | Что делать |
|---|---|
| «Генерация…» висит | проверьте Ollama: `curl http://localhost:11434/api/tags` |
| Нет вкладки AI | аддон не включён: Preferences → Add-ons → галочка |
| Модель не видит сцену | выключено «Отправлять снимок сцены» |
| Модель выдумывает | выключите снимок и сравните — так проверяется честность |
| Кнопок нет в панели | старая версия аддона: переустановите из `dist/` |
| Ответ на английском | Preferences → язык: Русский |
| Развёртка не удалась на гладком объекте | так и должно быть: у сферы нет угла для разреза — аддон сам переключается на автоматическую развёртку |
| Развёртка выглядит не так | поменяй «Швы по углу» в панели AI: меньше угол → больше швов → точнее, но больше островов |
| Плотность скачет между объектами | это и есть то, что показывает «Проверить UV» — выравнивание плотности запланировано (этап U3) |
