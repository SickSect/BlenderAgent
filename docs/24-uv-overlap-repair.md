# 24. Перекрытие UV: почему проверка ошибалась и как теперь раздвигаются острова

Эта глава — разбор одной конкретной кнопки и одной конкретной ошибки:

> «Я делаю проверку UV после развёртки, которую делает аддон, и нахожу
> пересекающиеся острова. А кнопка „Исправить перекрытие“ только увеличивает
> перекрывающиеся острова».

Симптом был настоящий, причин — две, и обе жили в коде:

1. **Проверка сравнивала габариты, а не полигоны.** У диагональных островов
   рамки пересекаются, хотя сами острова не делят ни одного пикселя. Отсюда
   «перекрытия» там, где их нет.
2. **Кнопка вызывала не тот инструмент.** `uv.pack_islands(scale=True)` — это
   не «раздвинуть», это «разложить всё заново и растянуть на всю текстуру».
   Зазор `0.001` на текстуре 2048 px — это два пикселя, то есть визуально ноль.

Ниже — что именно делает каждая часть, что она принимает, во что превращает и
кому отдаёт результат.

---

## 24.1. Что делает `uv.pack_islands` (и почему это не «раздвинуть»)

Представь, что у тебя на столе лежат карточки, а стол — это UV-квадрат `[0, 1]`.
`pack_islands` берёт **все** карточки и раскладывает их заново, как упаковщик:

```
что принимает:  все острова объекта (в Edit Mode), параметры укладки
что делает:     сортирует, поворачивает (если rotate=True), укладывает
                в квадрат, при scale=True — равномерно увеличивает всё,
                чтобы заполнить квадрат
что отдаёт:     новые UV-координаты; старую раскладку пользователя — нет
```

Два следствия:

- **`scale=True` — это не «подвинуть», а «растянуть».** Если нажать такую
  кнопку на объекте с перекрытием, острова становятся **больше** — ровно то,
  что видел пользователь.
- **`margin` — не «расстояние в пикселях».** При `margin_method="SCALED"`
  значение `0.001` масштабируется вместе с островом. На маленьком острове зазор
  получается почти нулевым.

Поэтому `pack_islands` остался там, где он хорош: в **«Развернуть»**, где
раскладки ещё нет и её не жалко. Для «у меня уже разложено, но два острова
налезли друг на друга» нужен другой алгоритм.

---

## 24.2. Проверка: два этапа вместо одного

Старый `_find_overlaps` сравнивал только прямоугольники:

```
box A: (u0, v0) .. (u1, v1)
box B: (u0, v0) .. (u1, v1)
если рамки пересекаются -> "перекрытие"
```

Это **широкая фаза** (broad phase): она дешёвая и никогда не пропускает
настоящее перекрытие. Но она даёт **ложные срабатывания**. Пример из теста
`part_overlap_precise`:

```
остров A: треугольник ниже линии u + v = 0.9
остров B: треугольник выше линии u + v = 1.1
рамки:    A (0..0.9, 0..0.9), B (0.1..1, 0.1..1)  -> пересекаются
полигоны: между ними полоса пустоты               -> перекрытия нет
```

Теперь после широкой фазы работает **узкая** (narrow phase): для каждой пары
островов, чьи рамки пересеклись, сравниваются уже **треугольники**.

### Как сравниваются два треугольника

Используется теорема о разделяющей оси (SAT). Идея: два выпуклых полигона не
пересекаются тогда и только тогда, когда существует прямая, на которую их
проекции не накладываются.

```
для каждого ребра обоих треугольников:
    берём нормаль ребра (ось)
    проецируем оба треугольника на эту ось -> два отрезка
    если отрезки не пересекаются -> полигоны разделены, выходим
если ни одна ось не разделила -> треугольники делят площадь
```

В коде это `_triangles_cross`. Важная деталь: сравнение идёт через `<=`, а не
`<`. Поэтому **касание рёбер не считается перекрытием** — два острова, у
которых общая граница, не борются за одни пиксели.

### Почему нужна ещё и сетка

Наивный вариант «каждый треугольник A против каждого треугольника B» — это
`N × M` проверок. На объекте с двумя большими диагональными островами, у
которых рамки пересекаются, а полигоны нет, это может быть миллион пар.

Поэтому внутри пары строится равномерная сетка по рамке большего острова:

```
каждый треугольник B кладётся в клетки, которые накрывает его рамка
каждый треугольник A проверяет только треугольники из своих клеток
```

Плюс аварийный бюджет `_TRIANGLE_TEST_BUDGET = 200_000` пар. Если бюджет
исчерпан, функция возвращает «перекрытие есть» — то есть остаётся
**консервативной**, а не врёт «всё чисто» без проверки.

Итог: `analyze()` теперь отвечает на вопрос «делят ли эти острова площадь», а
не «пересекаются ли их рамки». Это чинит и проверку, и отчёт доктора.

## 24.3. Раздвигание: минимальный сдвиг вместо новой раскладки

Новая функция — `repair_overlaps(obj, margin)` в `uv.py`. Кнопка и инструмент
`uv.fix_overlaps` вызывают именно её.

### Шаг 1. Собрать острова

`_collect_repair_islands` идёт по bmesh и собирает для каждого острова:

- список UV-петель (их и будем двигать);
- треугольники в UV-плоскости (для проверки);
- рамку `(u_min, v_min, u_max, v_max)`;
- площадь (пригодится, чтобы решать, кого двигать).

### Шаг 2. Найти настоящие перекрытия

`_overlap_pairs` — та же двухэтапная проверка: рамки, затем треугольники.
Возвращает список пар **один раз** (раньше каждая пара считалась дважды: A→B и
B→A).

### Шаг 3. Выбрать, кого двигать

Двигается остров с **меньшей площадью**. Логика простая: большой остров — это,
скорее всего, основная часть модели, её место дорого. Маленький остров дешевле
подвинуть.

### Шаг 4. Вычислить вектор побега

`_escape_vector` предлагает четыре направления и выбирает самое короткое:

```
вправо:  сдвинуть так, чтобы mover.u_min стал = other.u_max + gap
влево:   ... mover.u_max стал = other.u_min - gap
вверх:   ... mover.v_min стал = other.v_max + gap
вниз:    ... mover.v_max стал = other.v_min - gap
```

Формулы работают и для случая «один остров целиком внутри другого»: короткое
направление автоматически становится полным выходом наружу.

Дополнительное правило: если какой-то вариант **оставляет остров внутри
`[0,1]`**, он выигрывает даже при чуть большей длине. Иначе раскладка вылезет
за текстуру, и её придётся ужимать — а это потеря плотности.

`gap` — это зазор из настроек сцены (`Свойства сцены → UV → Island margin`,
по умолчанию `0.02`). Он не даёт островам снова соприкоснуться после
округлений.

### Шаг 5. Повторить проходы

Сдвиг одного острова может создать новое перекрытие с третьим. Поэтому
алгоритм делает до `max_passes = 24` проходов: на каждом заново ищет пары и
раздвигает их. Если за проход ничего не сдвинулось — выходим.

### Шаг 6. Вписать в текстуру

`_fit_into_texture` смотрит на общую рамку всех островов:

- если она шире/выше `[0,1]` — **вся раскладка** равномерно ужимается;
- затем сдвигается минимально, чтобы левый нижний угол был в `0,0`.

Важно: ужимается **всё вместе**, а не каждый остров по отдельности. Поэтому
соотношение размеров островов (и равномерность плотности) сохраняется. В
отчёте это поле `scale`: `0.93` значит «раскладка стала на 7% меньше».

### Шаг 7. Записать и проверить

`bm.to_mesh(mesh)` записывает UV обратно. Отчёт содержит:

```python
{
    "ok": True,
    "changed": True,
    "pairs_before": 3,   # сколько пар реально перекрывалось
    "pairs_after": 0,    # сколько осталось
    "moved": 2,          # сколько островов сдвинуто
    "scale": 1.0,        # во сколько раз ужали всю раскладку
}
```

Если перекрытий не было, `changed=False` и **ни одна UV-координата не
меняется**. Это проверяется тестом: второй запуск кнопки не двигает ни бита.

## 24.4. Что фича не чинит (и почему об этом надо сказать)

### Один остров, внутри которого UV наложены

Если два куска геометрии соединены и **не разделены швом**, для анализатора
это один остров. Внутри него UV может быть разорван (например, после
`smart_project`) или намеренно сложен — алгоритм этого не видит и не двигает:
двигать нечего, это одна группа.

Лечится швом: `Разрез по высоте`, ручной шов в Edit Mode или
`uv.mark_seams`. После шва появятся два острова, и кнопка сработает.

### Симметричная раскладка

`uv.symmetric` **намеренно** кладёт вторую половину на UV первой: одна
текстура обслуживает обе стороны. Такое перекрытие — не ошибка. Кнопку
«Исправить перекрытие» на симметричном объекте нажимать не надо: она честно
раздвинет половины и сломает замысел.

### UV-разрывы без швов

Анализатор собирает острова по **швам** (`_islands`), а не по UV-связности.
Для пайплайна аддона это работает: «Развернуть» само ставит швы. Но у
импортированной модели швов может не быть вовсе, хотя UV-шеллы уже разорваны.
Тогда анализатор увидит один остров и скажет «перекрытий нет».

Это ограничение — не баг кнопки, а следующий шаг «своего алгоритма UV»:
определять острова по UV-связности (совпадают ли UV на общем ребре), а швы
ставить по геометрии, а не только по углу. Об этом — в конце главы.

---

## 24.5. Почему не «просто увеличить margin у pack_islands»

Можно было бы ответить одной строкой: `pack_islands(margin=0.02)`. Но:

- он **перекладывает всё** — пользователь теряет свою раскладку;
- с `scale=True` он **меняет плотность**;
- с `scale=False` острова могут вылезти за `[0,1]`;
- и главное — он не решает проблему ложных срабатываний проверки: рамки
  диагональных островов всё равно могут пересекаться.

Раздвигание сохраняет всё, что можно сохранить, и меняет только то, что
действительно мешает.

---

## 24.6. Как проверить руками

1. Открой модель с перекрытием (или сделай два острова друг на друге).
2. `AI → UV → Проверить UV`. В отчёте должно быть `overlapping island pair(s)`.
3. `AI → UV → Исправить перекрытие UV`.
4. Повтори проверку: перекрытий быть не должно.
5. `Ctrl+Z` возвращает раскладку.

Автотесты (`tests/run_uv_check.py`):

- `part_overlap_precise` — рамки пересекаются, полигоны нет → перекрытия нет;
- `part_overlap_repair` — два одинаковых квадрата → одна пара, после ремонта
  ноль, размеры островов не изменились, второй запуск ничего не двигает;
- `part_unwrap` — после «Развернуть» куб чист.

Запуск:

```powershell
& "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" `
  --background --factory-startup --python tests/run_uv_check.py
```

## 24.7. Куда это ведёт: свой алгоритм UV для сложных объектов

Текущий пайплайн — «швы по углу → unwrap → укладка». Он хорошо работает на
hard-surface (кубы, детали, техника), потому что там угол 40° честно совпадает
с ребром жёсткости. На персонаже и на органике угол — плохой советчик.

Следующий слой (этап U6 в `docs/19-uv-roadmap.md`):

1. **Острова по UV-связности**, а не по швам. Это чинит и анализ импортированных
   моделей, и поиск перекрытий внутри одного шва-острова.
2. **Швы по геометрии**: короткие рёбра, скрытые области, симметрия, а не
   только двугранный угол.
3. **Развёртка сложных деталей**: сначала разрезать на «цилиндры/пластины»,
   потом unwrap каждую часть отдельно, потом укладывать.
4. **Проверка после укладки**: площадь, искажение, плотность и перекрытия —
   до того, как пользователь нажмёт «Проверить UV».

Кнопка «Исправить перекрытие» — это последний, страховочный шаг этого
пайплайна. Она не заменяет хорошую развёртку, но гарантирует, что в игру не
уедет модель с двумя островами в одном месте.
