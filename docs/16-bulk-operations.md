# Глава 16. Массовые операции: материал на сотню объектов

> 📦 `src/blender_addon/objects.py`, `operators.py` (`gaa.assign_to_selection`,
> `gaa.find_material_users`), `ui.py`, `i18n.py`, `tests/run_bulk_check.py`

Пять предыдущих глав были про **один** материал. Эта — про то, что
происходит, когда материалов и объектов много.

---

## 16.1. Почему это самая скучная работа в пайплайне

Сборка одного материала — творчество. А вот дальше начинается **бухгалтерия**:

- «назначи этот материал на все 80 объектов»;
- «я переделал материал — замени старый везде»;
- «кто ещё пользуется старым материалом?»
- «сделай из этих 40 объектов инстансы»;
- «сделай красную и синюю версию этого материала».

Каждая задача — минуты в интерфейсе, если делать руками, и **одна строка
кода**, если делать правильно. Это ровно тот случай, где аддон полезнее
человека: не потому что он умнее, а потому что не устаёт.

---

## 16.2. Слоты: где на самом деле живут материалы

Материалы хранятся **не на объекте**, а на его данных:

```
Object ──► data (Mesh) ──► materials[0], materials[1], ...
                  ▲
                  └── polygon.material_index — какая грань на каком слоте
```

Три следствия, которые определяют всю реализацию:

1. **У объекта может быть несколько слотов.** Назначение материала должно
   заменять **активный** слот, а не добавлять новый — иначе у объекта
   появится пятый слот.
2. **Замена материала в слоте сохраняет назначения граней.** Если грань
   указывает на слот 1, а слот 1 теперь смотрит на другой материал — грань
   по-прежнему на слоте 1. Ничего не «разъезжается».
3. **Инстанс разделяет и материалы.** Данные меша общие → слоты общие →
   материал общий.

⚠️ Слот может существовать и **не использоваться ни одной гранью** — если
все грани смотрят на слот 0, а в слоте 1 лежит материал «про запас». Поэтому
в отчёте «кто использует материал» для каждого слота указано число граней:
ноль означает «слот есть, но он не рисуется».

## 16.3. Назначение на выделение

```python
def assign_to_selection(material=None, objects=None):
    mat = _resolve(material)
    if mat is None:
        return []
    targets = list(objects) if objects is not None else selected_objects()
    changed = []
    for obj in targets:
        if materials.assign_material(obj, mat):
            changed.append(obj.name)
    return changed
```

`materials.assign_material` — та же функция, что и у кнопки «PBR из папки»:
активный слот заменяется, если слоты есть, иначе добавляется.

Поведение полностью совпадает с тем, что ожидает художник: «перетекстурить
объект» — это заменить его материал, а не добавить второй.

## 16.4. Замена везде

```python
for index in range(len(slots)):
    if slots[index] == old_mat:
        slots[index] = new_mat
```

Замена идёт **в слотах**, а не пересозданием объектов. Поэтому назначения
граней (`polygon.material_index`) остаются в силе, и материал, который
рисовался на половине куба, продолжает рисоваться на ней.

⚠️ Сравнение — через `==`, а не `is`: bpy выдаёт новую обёртку при каждом
обращении (глава 14, §14.9).

## 16.5. Вариант: «тот же материал, но красный»

Классический запрос: «нужны три оттенка одного дерева». Реализация — копия
мастера, у которой `Base Color` умножается на оттенок:

```
Текстура → [Variant Tint: MULTIPLY] → Base Color
                 ▲
                 └── RGB-узел с цветом оттенка
```

Код вставки:

```python
mix = tree.nodes.new("ShaderNodeMix")
mix.data_type = "RGBA"
mix.blend_type = "MULTIPLY"
mix.name = "Variant Tint"
```

⚠️ **Ловушка `ShaderNodeMix` в 4.x.** У узла **несколько сокетов с
одинаковыми именами**: `A` и `B` существуют отдельно для float, vector,
цвета и rotation. `node.inputs["A"]` вернёт **первый** — float-овый, а не
цветовой. Поэтому сокет надо искать по имени **и типу**:

```python
def _socket_by(collection, name, socket_type):
    for socket in collection:
        if socket.name == name and socket.type == socket_type:
            return socket
    return None

in_a = _socket_by(mix.inputs, "A", "RGBA")
in_b = _socket_by(mix.inputs, "B", "RGBA")
result = _socket_by(mix.outputs, "Result", "RGBA")
```

### Что делает вариант и что нет

| | Вариант (`make_variant`) | Инстанс (`make_instance`) |
|---|---|---|
| Что общего | изображения (датаблоки) | **всё**: меш, слоты, материал |
| Своё | своё дерево нод, свой оттенок | своя позиция и масштаб |
| Когда нужно | «три оттенка» | «200 одинаковых объектов» |

⚠️ Вариант — **независимая копия**: правка мастера его **не** затронет. Это
осознанно: варианты по смыслу расходятся. Если нужно наоборот — «один
материал на много объектов» — это **назначение** или **инстанс**, а не
вариация.

## 16.6. Инстансы и «single user»

```python
def make_instance(source, targets=None):
    for obj in targets:
        obj.data = source.data      # ← общие данные меша
```

После этого объекты — **инстансы**: правка меша меняет их все. Материалы тоже
общие, потому что слоты живут на данных меша.

Обратная операция:

```python
obj.data = obj.data.copy()          # каждому — своя копия
```

## 16.7. Очистка мусора

```python
for mat in list(bpy.data.materials):
    if mat.users == 0 and not mat.use_fake_user:
        bpy.data.materials.remove(mat)
```

Удаляются материалы и картинки, на которые **никто не ссылается**.
`use_fake_user` — это «держать, даже если не используется», и такие данные
не трогаются.

⚠️ Это **необратимо**. Инструмент `materials.cleanup_orphans` помечен как
**разрушающий**: модель его сама не запустит, а попросит вас нажать кнопку.

## 16.8. Как это проверяется

📦 `tests/run_bulk_check.py` — сцена из трёх кубов: один со «старым»
материалом, два с «новым».

```
== assign to selection
ok   two selected objects were touched (['BulkCube0', 'BulkCube1'])
ok   the active slot was replaced, not appended
ok   the other slot was left alone
ok   no extra slot was added
== find users
ok   three users found ([('BulkCube0', 0, 6), ('BulkCube1', 0, 6), ('BulkCube2', 1, 0)])
ok   a slot without faces is reported as zero
== replace everywhere
ok   three objects changed (['BulkCube0', 'BulkCube1', 'BulkCube2'])
ok   replacing again changes nothing
== instances
ok   the mesh data is shared now
ok   the mesh data is separate now
== variants
ok   the tint multiplies
ok   the tint colour is the one asked for
ok   the master was not touched
== cleanup
ok   the orphan was removed
RESULT: OK
```

⚠️ Тест поймал интересное: `str(material)` в Blender 5.x — это **не имя**, а
`<bpy_struct, Material("OldMat") at 0x...>`. Поэтому функция, ищущая материал
по имени, должна сначала распознать, что ей передали **сам датаблок**:

```python
if isinstance(name, bpy.types.Material):
    return name
```

Без этой проверки «найти материал по объекту» молча возвращал `None`, и все
операции выглядели как «ничего не нашлось».

## 16.9. Итог главы

- Массовые операции — это **бухгалтерия**, а не творчество: их должен
  делать код, а не человек.
- Материалы живут в **слотах данных меша**, а не на объекте. Замена в слоте
  сохраняет назначения граней.
- Назначение меняет **активный слот** — новых слотов не появляется.
- Отчёт «кто использует» показывает слот и **число граней**: слот без граней
  существует, но не рисуется.
- Вариант — **независимая копия** с умножением Base Color на оттенок;
  инстанс — **общие данные**. Это разные задачи, и инструменты разные.
- `ShaderNodeMix` в 4.x имеет несколько сокетов с **одинаковым именем** —
  искать надо по имени **и типу**.
- `str(material)` — не имя материала в Blender 5.x.
- Удаление неиспользуемых данных — **разрушающая** операция: модель её не
  запускает сама.
